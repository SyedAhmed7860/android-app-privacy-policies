Google Play Data Safety Disclosures

Application: ReceiptVault Package Name: com.receiptvaultapp Target API: Android 16 (API 36) Audited: October 2026
Verified Play Console Mapping

This document provides exact, verified answers for the Google Play Console Data Safety section. Every declaration is grounded directly in ReceiptVault's audited source code (package com.receiptvaultapp).

1. Global Data Safety Overview Questions

Question Verified Answer Technical Justification
Does your app collect or share any of the required user data types? Yes Google Mobile Ads (AdMob) processes advertising IDs on the free tier; Google Play Billing processes purchase tokens; Google Sign-In processes email for Drive OAuth.
Is all of the user data collected by your app encrypted in transit? Yes All network communications (Google Drive REST API, Google Play Billing, AdMob) use mandatory HTTPS / TLS 1.2+ encryption.
Do you provide a way for users to request that their data be deleted? Yes In-app "Delete All Data" feature, individual receipt deletion, and user control over their Google Drive backups.
Does your app allow users to create an account? No ReceiptVault does not operate a user account system. The Google Play Account Deletion URL requirement is therefore not applicable.

2. Data Types Breakdown

A. Photos and Videos

Field Play Console Declaration Details
Data Type Photos Receipt photos captured by user via camera or selected from device.
Collected? No (Local only) Stored strictly in private internal sandbox (context.filesDir/receipts). Never uploaded to developer servers.
Shared? No Never transmitted to third parties, advertising networks, or external AI providers.
Purpose App functionality Displaying receipt scans and transaction proof locally.

B. Financial Info

Field Play Console Declaration Details
Data Type Purchase History ReceiptVault Pro lifetime purchase token managed by Google Play Billing.
Collected? Yes (via Google Play Billing) Cryptographic purchase token received to unlock Pro features.
Shared? No Processed strictly between device and Google Play.
Data Type Other Financial Info (Expenses) Receipt amounts, tax, discounts, and merchant names.
Collected? No (Local only, optional Drive sync) Stored in Room SQLite. Transmitted only to user's personal Google Drive if backup is turned on.
Shared? No Never sold, shared with advertisers, or transmitted to ReceiptVault servers.

C. Personal Info

Field Play Console Declaration Details
Data Type Email Address User's Google account email obtained via Google Sign-In.
Collected? Yes (Optional) Only collected if user opts into Google Drive backup. Cached locally in DataStore to display linked account.
Shared? No Transmitted only to Google Identity OAuth for token validation.
Purpose Account Management (Drive Auth) Authorizing access to write backups into user's own Drive.

D. Device or Other Identifiers

Field Play Console Declaration Details
Data Type Device or Other IDs (Advertising ID / GAID) Google Advertising ID processed by Google Mobile Ads SDK on free tier.
Collected? Yes (by third-party SDK) Processed by Google AdMob for banner ads in the free version.
Shared? Yes (with Google AdMob) Shared with Google LLC for ad serving and fraud prevention.
Ephemerality Subject to Google's AdMob policy Users can reset their Advertising ID in Android Settings or upgrade to Pro.

3. Security Practices Declaration

  • Data Encrypted in Transit: Verified. All external traffic (Google Drive, AdMob, Billing) enforces HTTPS/TLS.
  • Data Deletion Request Mechanism: Verified. Users can erase all receipts, images, and backup records immediately in-app.
  • Independent Security Review: Verified offline-first architecture; code contains zero external analytics, tracking, or proprietary backend APIs.
